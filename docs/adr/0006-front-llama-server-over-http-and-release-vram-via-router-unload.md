# Front a user-run llama-server over HTTP and release VRAM through router-mode unload

The prompt assistant needs a local language model that shares one GPU with diffusion and video models. We talk HTTP to a `llama-server` the user starts and configures, and in the default policy we move ComfyUI's loaded models to RAM with `comfy.model_management.unload_all_models()` before the call and release the language model afterwards with the router-mode `POST /models/unload` endpoint. We rejected `llama-cpp-python` because it ties the pack to compiled, backend-specific wheels and keeps the model inside the ComfyUI process where it cannot be released cleanly, and we rejected spawning or stopping `llama-server` because the pack must not manage processes or install anything at runtime. The cost is that releasing VRAM is only possible when the user runs router mode; in single-model mode the node can only warn and point at `--sleep-idle-seconds`, since llama.cpp cannot move a loaded model between GPU and CPU.
