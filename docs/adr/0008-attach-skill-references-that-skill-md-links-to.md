# Attach the skill references that `SKILL.md` links to

Selecting a skill in `LFGG_PromptAssistant` attaches `SKILL.md` plus every attachable reference it links to, transitively, instead of `SKILL.md` alone. Skills written for coding agents tell the reader to "read `references/routing.md` first", but the model behind `llama-server` has no file or tool access, so with only `SKILL.md` attached it silently improvised the rules those references hold; the `scenario-maker-minimax-h3` skill sent 4 KiB of its roughly 140 KiB of linked guidance. Links are matched only against the skill's existing attachable-file list, so following them adds no new path surface, and every current scenario-maker skill stays under the 256 KiB attachment cap. The system message now also tells the model it cannot open files and names the selected skills' references that were left out, so it stops pretending to have read them. We rejected keeping explicit-only selection with a warning, because the default path stayed wrong for every skill shaped this way. The cost is a much larger system message (tens of thousands of tokens for the larger skills), which the server's context size must hold, and there is no way to select a skill without its linked references.
